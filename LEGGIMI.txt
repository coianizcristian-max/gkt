COSA FA IL CODICE
-----------------
1) Tre landing per gli annunci Google, una per gruppo di keyword:
     gkseason.it/lp/software-portieri
     gkseason.it/lp/allenamenti-portieri
     gkseason.it/lp/valutazione-portieri
   Senza menu, senza ricerca allenatori, senza prezzi: titolo che ripete la
   ricerca, un pannello disegnato (scheda portiere / settimana / valutazione),
   3 vantaggi, come funziona, chi l'ha fatto, 4 FAQ, chiusura. Due soli
   pulsanti: "Crea l'account gratis" (-> /registrati?ruolo=allenatore) e
   "Apri la demo senza registrarti" (-> /d).
   Statiche, pre-generate al build, noindex (X-Robots-Tag + meta + robots.txt):
   non competono con la home su Google. AdsBot le legge comunque.
   Testi in lib/landingAds.js: per cambiare una frase modifichi solo quello.

2) Tag di conversione Google Ads (gtag.js), app/components/GoogleAds.js.
   Parte SOLO dopo il consenso cookie, come Pixel e PostHog. Due conversioni:
     'registrazione'  da RegistratiClient (solo auto-registrazioni, non inviti)
     'demo'           da DemoTracker (ingresso ospite da /d)
   Senza le variabili d'ambiente non carica niente.

3) Attribuzione: AttribuzioneUtm salva anche gclid/gbraid/wbraid (clic Google)
   e /api/ospite li fa sopravvivere al redirect della demo. Su PostHog le
   registrazioni da Google avranno utm_source=google + gclid.

4) /registrati?ruolo=allenatore salta la domanda "chi sei?" e mostra subito
   il modulo del preparatore (un passaggio in meno per chi arriva da annuncio).

5) CSP in next.config.mjs: aggiunti i domini Google (googletagmanager,
   googleadservices, google.com/.it, doubleclick). Senza, il tag sarebbe bloccato.

Niente migrazioni SQL. Niente file di traduzione toccati (le landing sono
solo in italiano, per scelta: le campagne sono italiane).

Per la campagna META non serve nessun codice nuovo: DemoAperta, UTM e Pixel
c'erano gia'. Le istruzioni sono in meta-ads/CAMPAGNA-META.md.

DEPLOY — ORDINE CONSIGLIATO
---------------------------
1) Google Ads: crea le due azioni di conversione e prendi ID + etichette
   (google-ads/CAMPAGNA-GOOGLE.md, parte A). Se vuoi deployare prima, va
   bene lo stesso: senza variabili il tag resta spento, le landing funzionano.

2) Variabili d'ambiente (Vercel: Production + Preview + Development; e .env.local)
     NEXT_PUBLIC_GADS_ID                  = AW-xxxxxxxxx
     NEXT_PUBLIC_GADS_LABEL_REGISTRAZIONE = <etichetta "Registrazione">
     NEXT_PUBLIC_GADS_LABEL_DEMO          = <etichetta "Demo aperta">
   NB: sono NEXT_PUBLIC_, entrano nel bundle al build -> dopo averle messe
   serve un redeploy (o il push di questo pacchetto, che lo provoca).

3) Scompatta lo zip sopra D:\SITO\GKT (sovrascrivi), poi:

     cd D:\SITO\GKT
     git config user.email
         (deve stampare coianiz.cristian@gmail.com, altrimenti:
          git config user.email coianiz.cristian@gmail.com)
     git add -A
     git status
         (devi vedere i 13 file dell'elenco sopra, niente altro)
     git commit -m "Landing annunci /lp, tag conversione Google Ads, gclid in attribuzione"
     git push origin main

4) Dopo il deploy, dal telefono:
     - apri https://www.gkseason.it/lp/software-portieri  -> landing, due pulsanti
     - "Crea l'account gratis" -> modulo subito visibile, senza "chi sei?"
     - "Apri la demo senza registrarti" -> entri in demo come prima
     - https://www.gkseason.it/lp/qualcosa -> pagina non trovata
     - console browser: nessun "Refused to load ... Content Security Policy"
       dopo aver accettato i cookie
     - PostHog: la pagina compare come "Landing annunci: software portieri"

5) Poi le campagne, nell'ordine: Meta Fase 0-1 oggi (pubblici), reel in
   settimana, Google Search appena hai le etichette.

  (con le parentesi quadre) e che lib/landingAds.js esista.

  deploy non rifatto; oppure i cookie non sono stati accettati nel test.

- Rollback: git revert HEAD (i file nuovi non danno fastidio se restano).
